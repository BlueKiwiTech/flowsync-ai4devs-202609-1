# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FlowSync is a course practice project (team task management). Two independent npm projects, no root `package.json` / workspace:

- `backend/` — REST API on AdonisJS 7 (Lucid ORM on SQLite, VineJS, `@adonisjs/auth` access tokens). Runs on `http://localhost:3333`.
- `frontend/` — React 19 + Vite + TypeScript, Tailwind v4 + shadcn/ui (`src/components/ui/`, generated by `npx shadcn add`), `react-router` (declarative `BrowserRouter`). Auth screens: `/login`, `/signup`, protected `/profile`. Runs on `http://localhost:5173`.

Project docs (`README.md`, `prompts.md`) are in Spanish.

## Commands

From the repo root (`Makefile`, POSIX sh only so it runs on macOS's make 3.81, Linux and WSL; kept LF via `.gitattributes`):

```bash
make setup   # npm ci both projects, create .env files, APP_KEY only if empty, migration:run (idempotent)
make start   # backend + frontend as background jobs; trap sends SIGINT to the group (ace serve ignores SIGTERM), so Ctrl+C or one side dying stops both; refuses if ports 3333/5173 are busy
```

Backend (run from `backend/`):

```bash
npm install
cp .env.example .env && node ace generate:key   # first time only
node ace migration:run      # creates tmp/db.sqlite3 and regenerates database/schema.ts
npm run dev                 # node ace serve --hmr
npm run lint                # eslint (@adonisjs/eslint-config)
npm run typecheck           # tsc --noEmit
npm run format              # prettier (@adonisjs/prettier-config)
npm test                    # node ace test (Japa)
node ace test functional    # one suite (unit | functional)
node ace test --files=tests/functional/auth.spec.ts   # one file
node ace test --tests="logs in a user"                # one test by title
node ace make:controller <name> / make:model / make:migration / make:validator
node ace list:routes
```

Test suites are declared in `backend/adonisrc.ts`: `unit` → `tests/unit/**/*.spec.ts`, `functional` → `tests/functional/**/*.spec.ts` (the functional suite boots the HTTP server). No test files exist yet. Tests use `.env.test` (`SESSION_DRIVER=memory`) and the same SQLite file.

Frontend (run from `frontend/`):

```bash
npm install
npm run dev       # vite
npm run build     # tsc -b && vite build (this is the typecheck)
npm run lint      # oxlint (.oxlintrc.json)
```

The frontend has no test runner; `npm run format` runs Prettier (also applied automatically by the Claude Code hook on edit).

## Frontend architecture

- `@/*` alias → `src/*` (configured in `tsconfig.json`, `tsconfig.app.json`, `vite.config.ts`).
- `src/lib/api.ts`: `fetch` wrapper for the backend (`VITE_API_URL`, default `http://localhost:3333`), unwraps `{ data }`, throws `ApiError { status, errors }` (`status` 0 = network failure). Add new endpoint helpers here.
- `src/lib/errors.ts`: maps `ApiError` to user-facing messages — never show raw API errors or log them to the console.
- `src/auth/`: `AuthProvider` keeps the access token in `localStorage` (`flowsync.token`); `useAuth()` lives in `auth-context.ts`; `RequireAuth` guards protected routes. A 401 from the API clears the token.
- `src/pages/`: one component per route, built with shadcn `Card`/`Input`/`Alert`.

## Backend architecture

- **Routes** live in `start/routes.ts`, all under `/api/v1`. Controllers are referenced through the generated `controllers` map (`import { controllers } from '#generated/controllers'` → `[controllers.AccessTokens, 'store']`), not by importing controller files directly. Protected groups use `.use(middleware.auth())`; named routes via `.as()` feed the Tuyau registry.
- **Current endpoints**: `POST /api/v1/auth/signup`, `POST /api/v1/auth/login` (both return `{ data: { user, token } }`), `GET /api/v1/account/profile`, `POST /api/v1/account/logout` (Bearer token required).
- **Auth**: default guard is `api` (opaque access tokens, `DbAccessTokensProvider` on `User`). A session `web` guard is also configured but unused by the routes. `silent_auth_middleware` runs `auth.check()` on every request.
- **Responses**: `providers/api_provider.ts` adds `ctx.serialize()`, which wraps output in `{ data: ... }` (and Lucid pagination meta). Controllers return `serialize(SomeTransformer.transform(model))`; transformers in `app/transformers/` (extending `BaseTransformer`, using `this.pick`) define the public shape — never return models directly. `force_json_response_middleware` forces JSON for all responses, including errors.
- **Validation**: VineJS validators in `app/validators/`, created with `vine.create({...})` and used via `request.validateUsing(...)`. `start/validator.ts` globally transforms Vine dates into Luxon `DateTime`.
- **Models / schema**: `database/schema.ts` is **auto-generated** from migrations by `node ace migration:run` (do not edit). Models extend the generated `*Schema` classes (e.g. `class User extends compose(UserSchema, withAuthFinder(hash))`) and add only relations, computed getters and behavior. To add columns: write a migration, run it, then use the regenerated schema class. Custom type mapping goes in `database/schema_rules.ts`.
- **Generated code**: everything in `.adonisjs/` (controllers index, events, Tuyau client registry under `.adonisjs/client/`) is regenerated by the `adonisrc.ts` init hooks (`indexEntities`, `generateRegistry`) when the dev server / ace commands run. Do not edit by hand. The registry is exported from `backend/package.json` as `backend/registry` and `backend/data` for a typed client (`@tuyau/core`).
- **Imports**: use the `#` subpath aliases from `backend/package.json` (`#models/*`, `#controllers/*`, `#validators/*`, `#transformers/*`, `#start/*`, `#config/*`, `#generated/*`, …) with no file extension, not relative paths.
- **CORS**: in dev every origin is allowed with credentials (`config/cors.ts`); production allowlist is empty.
- Naming follows Adonis conventions: snake_case filenames (`access_tokens_controller.ts`), PascalCase classes, camelCase model properties mapped to snake_case columns.

# Process Rules

- Before touching any code: create a new branch (`git checkout -b feat/<slug>`). Never commit directly to `main` or `s1/start`.
- When completing the task: use the `/commit` skill, then run `gh pr create` with a complete description of the changes in the PR body.
- After opening the PR: run the `adversarial-reviewer` subagent against it before considering the task complete.
- Do not repeat that summary in the chat: the session will be lost, but the PR will remain. Respond only with the PR URL.
- Run e2e tests using the Chrome extension and end adding a gif of the journey in a new comment of the github PR.
